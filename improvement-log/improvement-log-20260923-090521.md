### 2026-09-23 — Two known SwiftUI traps shipped to the audit

**What happened:** The Digest thumbnail used `Image.resizable().scaledToFill()` inside `.frame(maxWidth: .infinity, maxHeight: .infinity)`; the fill image sized the tile to its own aspect ratio and overflowed the fixed-height row onto the text. The row also set `.accessibilityIdentifier` without `.accessibilityElement(children: .contain)`, hiding every thumbnail's id — a trap already written down in `project_noto2_target` memory.
**What better looks like:** For fixed tiles, size a `Color.clear` frame first and put the image in `.overlay { … scaledToFill() }` + `clipShape`. Before adding an identifier to a container, add `.contain`. Dump the a11y tree in the self-check (I only looked at a screenshot of a single-video card, where the overflow was less visible).

### 2026-09-23 — viewWillDisappear is the wrong place to stop an embedded AVPlayerViewController

**What happened:** Inline video stopped on `viewWillDisappear` of the host editor controller. Tapping the native full-screen button made AVKit present `AVFullScreenViewController`, which calls the host's `viewWillDisappear` *before* `playerViewController(_:willBeginFullScreenPresentationWithAnimationCoordinator:)`, so the `isFullScreen` guard was still false; the child was removed and AVKit logged "was deallocated while its contents were being presented full screen".
**What better looks like:** Stop embedded players in `viewDidDisappear` (the full-screen delegate has fired by then) and guard on the delegate's flag. Read the AVKit log lines in the simulator (`log show --info --predicate 'process == "Noto2" AND subsystem CONTAINS "AVKit"'`) — they named the problem immediately.

### 2026-09-23 — Videos should fill the editor width

**What happened:** Video thumbnails reused the image overlay sizing, which shrinks a portrait image to a narrow tile at the capped height. Eugene: "The video should fill the width of the editor space."
**Why it matters:** A video is a player surface, not a picture; a narrow tile next to a full-width landscape video looks broken, and the native player letterboxes anyway.
**What better looks like:** Give media players a consistent full-width box (letterbox/pillarbox inside) from the start; only still images keep their natural shape.

### 2026-09-23 — Media layout checked only at the end of a note

**What happened:** I verified the full-width portrait video in a note where it was the last line. The iOS overlay was capped at 284 pt but the TextKit line still reserved the uncapped aspect height (656 pt), leaving a ~379 pt empty band before any following text. The independent auditor found it with a note that had text after the video.
**Why this was wrong:** Two different pieces of code decide the drawn size (overlay) and the reserved size (layout fragment). Checking only the last line hides any mismatch between them.
**What better looks like:** For any change to embedded media sizing, check media with text directly above and below it, and assert in a unit test that reserved height == drawn height + padding (now `cappedFragmentHeightMatchesOverlay`).
