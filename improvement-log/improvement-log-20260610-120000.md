## Log

### 2026-06-10 — macOS unit tests destroyed the real app's vault bookmark

**What happened:** Running `flowdeck test -D "My Mac"` launched the app-hosted test runner, which executes the real `NotoApp` lifecycle including `VaultLocationManager.resolveVault()` against the REAL user-level defaults domain (`~/Library/Preferences/com.eugenechan.Noto.plist`). Test processes failed bookmark resolution and ran `clearSavedExternalVaultState()`, left a 0-byte `vaultBookmarkData`, and even wrote a simulator path into `lastOpenedNoteURL`. Next real app launch showed the vault-setup screen — Eugene's vault config was gone.
**Why this was wrong:** App-hosted unit tests must never mutate the daily-driver app's persisted state. The test host shares the bundle ID and (unsandboxed) defaults domain.
**What better looks like:** (1) Code fix: detect XCTest in `VaultLocationManager` (or NotoApp) and use an isolated `UserDefaults(suiteName:)`/skip resolve+clear under test. (2) Until fixed, do not run `flowdeck test -D "My Mac"` on a machine where Noto is in daily use without backing up `~/Library/Preferences/com.eugenechan.Noto.plist` first.

### 2026-06-10 — FlowDeck macOS builds are unsandboxed (no entitlements)

**What happened:** `flowdeck build -D "My Mac"` produces an adhoc/linker-signed Noto with no entitlements, despite `CODE_SIGN_ENTITLEMENTS = Noto/Noto.entitlements` in the project. The installed app therefore runs unsandboxed and reads `~/Library/Preferences/` instead of the container. Security-scoped bookmarks created by a sandboxed build (in the container plist) cannot be resolved by it, and vice versa.
**Why this matters:** Sandbox behavior differs between dev installs and production; CLAUDE.md's macOS runtime rules assume `com.apple.security.files.user-selected.read-write` is present. Permission bugs are masked in dev and appear only in release builds.
**What better looks like:** Investigate making the install flow use a properly signed build (Xcode automatic signing applies the entitlements), or explicitly document that dev installs are unsandboxed.

### 2026-06-10 — Security-scoped bookmarks cannot be transplanted between processes

**What happened:** Tried restoring the vault by writing a valid bookmark (from the container plist, then a freshly minted one from a Swift script) into the app's defaults. Resolution always failed (Code=259) — `scopedbookmarksagent` binds scoped bookmarks to the creating process identity. Only the app's own folder re-pick (NSOpenPanel → `setVault`) creates a usable token.
**What better looks like:** When a vault bookmark is corrupt, go straight to driving the app's own "Open Existing Vault" flow (UI automation or ask Eugene) instead of attempting defaults surgery. Also: this session's sandbox intercepts `defaults`/cfprefsd writes — verify on-disk plist state with `plutil -p`, and flush cfprefsd BEFORE editing plists, never after.

### 2026-06-10 — DebugTrace concurrent-write race loses events

**What happened:** A launch that logged 2 vault errors to os_log left only "app init" in `DebugTraceEvents` — concurrent `record()` calls each do read-append-write on the array, so the last writer wins and earlier events vanish.
**What better looks like:** Serialize `DebugTrace.record` through a lock/queue, or append via a single actor.
