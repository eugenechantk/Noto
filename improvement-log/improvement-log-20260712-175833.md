### 2026-07-13 — cfprefsd wedge from direct plutil edit of a live container plist

**What happened:** Used `plutil -remove DebugTraceEvents` directly on `~/Library/Containers/com.eugenechan.Noto/.../com.eugenechan.Noto.plist` while the app was running. Later `defaults read` and `plutil -extract` on that domain hung indefinitely (killed at 30–45s timeouts several times).
**Why this was wrong:** cfprefsd caches domains; editing the backing file behind its back desyncs it. Known macOS footgun.
**What better looks like:** Always go through `defaults` (host API) for pref mutations, even for container plists (`defaults delete <full-plist-path> <key>` routes through cfprefsd). If a domain wedges: `killall cfprefsd` (safe, it respawns) instead of retrying reads.

### 2026-07-13 — FlowDeck appLaunch env did not reach the macOS app

**What happened:** `flowdeck run --config <json with appLaunch.env NOTO_DEBUG_TRACE=1>` launched the app but the env-gated DebugTrace stayed disabled (no events at all despite DEBUG build).
**Why this matters:** Wasted a full build/launch/repro cycle before noticing the trace was empty.
**What better looks like:** For macOS debug toggles prefer the UserDefaults fallback (`defaults write <container-plist> EnableDebugTrace -bool true` + app restart) — verified working. Worth testing whether FlowDeck's appLaunch env works for macOS launches at all; if not, report upstream.

### 2026-07-13 — Background-unreachable SwiftUI menu commands need an in-app debug hook

**What happened:** Could not trigger Noto's ⌘K Search from automation: pid-targeted CGEvents, global CGEvents (even with app frontmost), and AXPress on the SwiftUI menu item all silently failed — the command is gated on key/main window (`NotoCommandTarget.matches`), which never holds for an unfocused app; AXPress on SwiftUI MenuBarItems returns success without dispatching.
**Why this matters:** Burned ~40 min on trigger attempts before instrumenting.
**What better looks like:** For app-command automation on macOS, add a DEBUG-only DistributedNotificationCenter command hook early (now exists: `NotoDebug.command` → `openSearch` in NoteListView; extend with more commands as needed). Documented in bug-reports/024.
